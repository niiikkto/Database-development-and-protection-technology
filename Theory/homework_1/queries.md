# Запросы к коллекции `shop.orders`

Предметная область: заказы интернет-магазина кофейного оборудования.
В коллекции 5 документов (`1 – 5 of 5`). Формы документов различаются:

- у A-1002 нет полей `tags` и `promo_code`;
- у A-1003 есть дополнительное поле `comment`;
- у A-1004 `tags` — пустой массив;
- у A-1001 и A-1005 есть `promo_code`, у остальных нет.

## Пять рабочих запросов

| № | Что ищем | Фильтр | Найдено |
|---|----------|--------|---------|
| 1 | Точное совпадение | `{ status: "delivered" }` | 2 из 5 |
| 2 | Вложенное поле | `{ "customer.city": "Ярославль" }` | 3 из 5 |
| 3 | Элемент массива | `{ tags: "подарок" }` | 2 из 5 |
| 4 | Сравнение | `{ total: { $gt: 5000 } }` | 3 из 5 |
| 5 | Наличие поля | `{ promo_code: { $exists: true } }` | 2 из 5 |

Пояснения:

1. Ищет заказы со статусом ровно «delivered»: это A-1001 и A-1003.
2. Точка заходит внутрь объекта `customer`; находит Петрова, Козлова и Орлова.
3. Условие проверяется для каждого элемента массива `tags`; у A-1004 массив пустой, у A-1002 поля нет вообще — оба не найдены.
4. `$gt` — строго больше; работает, потому что `total` хранится числом. Находит A-1001 (12400), A-1003 (7800), A-1005 (5600).
5. Находит заказы, где поле `promo_code` существует: A-1001 и A-1005.

Вариант запроса 4 с Options: Project `{ number: 1, total: 1, _id: 0 }`, Sort `{ total: -1 }`
— порядок результата: A-1001, A-1003, A-1005.

## Один сломанный запрос

Фильтр: `{ "customer.city": Ярославль }` (без кавычек у значения).

Это **ошибка разбора**, а не пустой результат. Compass разбирает фильтр у себя
и считает `Ярославль` именем переменной, а не строкой. Рамка поля становится
красной, кнопка Find недоступна, запрос на сервер не уходит, список документов
не меняется.

Пустой результат выглядел бы иначе: например, `{ "customer.city": "ярославль" }`
(другой регистр) разбирается нормально, запрос уходит на сервер, а счётчик
показывает `0 – 0 of 0` при обычной рамке.

## Абзац о цене

В каждом заказе продублированы имя клиента и город (`customer`), а также
название и цена товара (`items.title`, `items.price`). Это сделано осознанно:
карточка заказа открывается одним обращением, без соединений. Цена изменения
другая: если, например, товар «Кофемашина» переименуют или клиент переедет в
другой город, придётся обновить каждый документ, где это значение встречается.
Для 5 заказов это 1–3 правки, а если заказов станет двести, а клиент сделал
двадцать из них, правок будет двадцать. Зато цена, по которой товар был продан,
должна остаться в заказе как есть — здесь дублирование как раз нужно.
